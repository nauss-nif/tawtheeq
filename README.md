# توثيق — منصة توثيق الدورات التدريبية

منصة ويب لإدارة وتوثيق صور وفيديوهات الدورات التدريبية، وإنتاج **مجلة إلكترونية** لكل دورة تُشارك مع المتدربين عبر رابط عام غير قابل للتخمين. مبنيّة على هوية **جامعة نايف العربية للعلوم الأمنية**، واجهة عربية بالكامل (RTL) بخط IBM Plex Sans Arabic.

---

## الحزمة التقنية

| الطبقة | التقنية |
|--------|---------|
| الواجهة | Next.js 14 (App Router) + TypeScript + Tailwind CSS |
| قاعدة البيانات والمصادقة والتخزين | Supabase (PostgreSQL + Auth + Storage + RLS) |
| معالجة الصور | Sharp (تحسين إضاءة/ألوان، WebP، مصغّرات متعددة) |
| معالجة الفيديو | ffmpeg عبر fluent-ffmpeg (H.264/CRF، thumbnail، المدة) |
| توليد PDF | @react-pdf/renderer |
| الأرشفة | Microsoft Graph API (SharePoint) عبر @azure/msal-node |
| الحركة | Framer Motion · الأيقونات: lucide-react · التنبيهات: sonner |

---

## المتطلبات المسبقة

- Node.js 20+
- مشروع Supabase (مجاني يكفي للبداية)
- **ffmpeg + ffprobe** مثبّتان على الخادم الذي يعالج الفيديو (لمعالجة الفيديو فقط)
- (اختياري) تسجيل تطبيق Azure AD بصلاحية `Sites.ReadWrite.All` لأرشفة SharePoint

## الإعداد خطوة بخطوة

### 1) تثبيت الاعتماديات
```bash
npm install
```

### 2) متغيرات البيئة
انسخ `.env.example` إلى `.env.local` واملأ القيم:
```bash
cp .env.example .env.local
```
أهم المتغيرات:
- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`
- `ADMIN_EMAIL` / `ADMIN_PASSWORD` — لإنشاء حساب المدير (الافتراضي: `nalshahrani@nauss.edu.sa`)
- `ALLOWED_EMAIL_DOMAIN=nauss.edu.sa` و`ENFORCE_EMAIL_DOMAIN=true` — قيد نطاق بريد المنسقين (اجعلها `false` للتعطيل)
- متغيرات Azure/SharePoint للأرشفة

> **أمان:** لا تُكتب أي بيانات اعتماد في الكود. كل الأسرار تُقرأ من البيئة فقط.

### 3) تهيئة قاعدة البيانات (المخطط + RLS)
نفّذ ملفات الهجرة في `supabase/migrations/` بالترتيب عبر لوحة Supabase (SQL Editor) أو Supabase CLI:
```bash
# عبر CLI
supabase db push
# أو الصق محتوى الملفات بالترتيب في SQL Editor:
# 0001_initial_schema.sql → 0002_rpc_and_storage.sql
# → 0003_promo_studio.sql → 0004_promo_library.sql
```
هذا يُنشئ الجداول (`profiles`, `courses`, `media`, `magazine_sections`)، الدوال، الـ triggers، **سياسات RLS**، ودلاء التخزين (`media-processed` عام، `media-original` خاص).

### 4) إنشاء حساب المدير (seed)
```bash
npm run seed:admin
```
يقرأ `ADMIN_EMAIL`/`ADMIN_PASSWORD` من البيئة، ويُنشئ مستخدمًا بدور `admin` وحالة `active`.

### 5) التشغيل
```bash
npm run dev      # التطوير
npm run build && npm start   # الإنتاج
```
افتح `http://localhost:3000`.

## الأدوار والحسابات

- **المدير** (`admin`): صلاحية كاملة. زر في الشريط العلوي للتبديل بين **وضع المدير** (اعتماد الحسابات، إدارة المنسقين، كل الدورات، الإحصائيات) و**وضع الموظف** (يستخدم المنصة كمنسق عادي). يُنشأ عبر seed فقط.
- **المنسق** (`coordinator`): تسجيل ذاتي (`/auth/register`) ببريد `@nauss.edu.sa`. الحساب `pending` حتى يعتمده المدير — تظهر له صفحة «حسابك بانتظار التفعيل». بعد الاعتماد يدير دوراته وينشر مجلاته مباشرة.
- **المتدرب**: لا حساب — يفتح المجلة عبر `/m/[slug]` (slug عشوائي 14 حرفًا).

## خط معالجة الوسائط (هجين: Supabase + SharePoint)

عند رفع ملف (`POST /api/courses/[courseId]/media`):
1. **الصور (Sharp):** auto-orient، normalize، تحويل WebP بجودة متكيّفة (تُخفَّض حتى يبقى الناتج ≤ 800KB)، أقصى بُعد 2000px، مصغّرات 400px و1200px. كشف الصور شديدة الظلام/الضبابية (`is_low_quality`) لاستبعادها من العرض الافتراضي.
2. **الفيديو (ffmpeg):** 1080p H.264 بـ CRF 26، خفض تلقائي إلى 720p إن تجاوز 100MB، thumbnail من أول لقطة، استخراج المدة.
3. **الرفع:** النسخة المضغوطة والمصغّرات إلى `media-processed` (عام).
4. **الأرشفة:** النسخة الأصلية تُرفع إلى SharePoint (مجلد لكل دورة `اسم-الدورة_تاريخ-البداية`) عبر Graph API، مع **upload session** للملفات > 4MB و**إعادة محاولة 3 مرات**.
5. **التنظيف:** بعد نجاح الأرشفة لا تُخزَّن النسخة الأصلية في Supabase (`original_url = null`) — تبقى المساحة صغيرة والأصل محفوظ في SharePoint.
6. الواجهة تتابع `processing_status` و`archive_status` **لحظيًا** عبر Supabase Realtime، وتعرض نسبة التوفير.

> **الفيديو والبيئات بلا خادم دائم:** المعالجة تتم داخل طلب الرفع (`maxDuration=300`). للأحمال الكبيرة يُنصح بنقل معالجة الفيديو إلى قائمة انتظار/دالة serverless مخصصة تستدعي نفس دوال `src/lib/media/`. عامل `scripts/media-worker.ts` يرصد الأرشفة الفاشلة للمراجعة.

## المجلة والقوالب

- ثلاثة قوالب مبنية على الهوية: **كلاسيكي** / **عصري** / **احتفالي** (`src/features/magazine/templates.ts`).
- المجلة العامة صفحة تفاعلية: غلاف hero، تعريف، معرض صور (lightbox + lazy loading)، فيديوهات، مدربون، خاتمة.
- **وضع Flipbook** (مكتبة page-flip) وزر **تنزيل PDF**.
- مؤشر تقدم قراءة ذهبي، شريط تنقل يتحول لأخضر عند التمرير، scroll-spy، احترام `prefers-reduced-motion`.
- **الخصوصية:** المجلات `noindex`، وزيادة `views_count` عند كل زيارة عبر RPC آمنة.
- **Open Graph** لمعاينة جميلة عند المشاركة في واتساب.

### ملاحظة حول PDF العربي
`@react-pdf/renderer` يدعم العربية بشكل محدود في تشكيل الحروف (الوصل/الاتجاه). للحصول على تشكيل مثالي في الإنتاج، يمكن استبدال مسار `/m/[slug]/pdf` بتوليد عبر **Puppeteer** (طباعة صفحة المجلة نفسها إلى PDF) — وهو مذكور كخيار بديل ضمن الحزمة التقنية.

## «الاستوديو الذكي للبرومو» (AI Promo Studio)

وحدة متكاملة داخل صفحة البرنامج (تبويب **٥. البرومو**) تنتج فيلمًا ترويجيًا قصيرًا
من مواد البرنامج: تحلّل الصور والفيديوهات، تختار أفضلها، تبني قصة بصرية، تحرّك
الصور بحركة كاميرا سينمائية، تنتج التعليق الصوتي والموسيقى، وتُخرج MP4 جاهزًا.

### الرحلة

```
اختيار البرنامج → رفع المواد (تبويب الصور) → نصوص اختيارية → المدة → الاتجاه
→ النمط → الصوت → الموسيقى → «إنشاء البرومو» → معاينة → تعديل → تصدير
```

الافتراضات جاهزة للعمل فورًا: **٦٠ ثانية، أفقي، سينمائي، موسيقى + تعليق، شعار الجامعة**.

### البنية (Modular Providers)

كل خدمة خارجية خلف Adapter مستقل في `src/lib/promo/providers/`. تغيير المزوّد
يتم من متغيّر بيئة واحد أو بإضافة ملف وتسجيله في `providers/index.ts` — دون لمس
محرّك القصة أو التكوين أو الرندر.

| الطبقة | المزوّد الافتراضي | البديل عند الغياب |
|---|---|---|
| `tts` | ElevenLabs ← OpenAI | موسيقى فقط، والنص يظهر على الشاشة |
| `llm` | Anthropic ← OpenAI | نص مبني من بيانات البرنامج مباشرة |
| `i2v` | `motion` (ffmpeg، مدمج) | متاح دائمًا — لا يحتاج مفتاحًا |
| `genvideo` | Replicate (اختياري) | تُستخدم أفضل مادة كلقطة افتتاحية |
| `render` | ffmpeg | — |
| `analysis` | محلّي (Sharp) | متاح دائمًا |
| `music` | مكتبة في دلو `promo` | رفع ملف خاص بالمستخدم |
| `storage` | Supabase Storage | — |

كل المفاتيح تُقرأ على الخادم فقط (`serverEnv.promo`) ولا تصل الواجهة إطلاقًا.

### كيف يعمل الإنتاج

1. **التحليل** (`analyze.ts` + `providers/analysis/local.ts`) — قياس فعلي للحدّة
   والإضاءة والتباين وغنى الألوان والإنتروبيا واتزان التكوين، واستخراج نقطة
   التركيز البصري، وبصمة إدراكية (dHash) لكشف الصور المتكرّرة. النتائج تُخزَّن
   في `media_analysis` وتُعاد استخدامها بين البروموهات.
2. **الاختيار** — استبعاد ما دون عتبة الجودة والمكرّر بصريًا، مع احترام أي
   تضمين/استبعاد يدوي.
3. **القصة** (`story.ts`) — تسلسل من عشر خطوات يُكيَّف حسب المحتوى (تُحذف خطوة
   «المكان» بلا مكان مسجّل، وتُدمج «الأنشطة» في «التدريب» عند تقارب المواد…).
   **مدة الفيديو التزام**: عند ندرة المواد يُعاد استخدام الأفضل بتأطير وحركة
   مختلفين، بتوزيع متوازن ومنع تجاور النسختين — لا فيلم أقصر من المطلوب.
4. **النص** (`script.ts`) — نص المستخدم يُلتزم به حرفيًا؛ التحسين يتم بطلبه فقط.
   بلا نص، يُكتب من بيانات البرنامج وحدها بطول مطابق للمدة وسرعة القراءة.
5. **الصوت** — عشرة أصوات عربية بمعاينة قبل الاختيار، وقاموس نطق
   (`promo_pronunciations`) يراعي السوابق العربية الملتصقة (ال، و، ب، ل، ك).
6. **التكوين** (`timeline.ts`) — يُبنى **مستقلًا لكل اتجاه**: نقطة التركيز وحركة
   الكاميرا ومواضع النصوص وأحجامها والمناطق الآمنة كلها تُعاد حسابها. لا اقتصاص
   ولا Letterboxing.
7. **الرندر** (`providers/render/ffmpeg.ts`) — كل مشهد يُرندر إلى مقطع وسيط، ثم
   تُدمج المقاطع بـ `xfade` ويُركَّب الصوت. هذا ما يجعل «إعادة توليد هذا المشهد»
   لا تعيد بناء الفيلم كلّه. الموسيقى تنخفض أثناء الكلام عبر `sidechaincompress`
   ثم تُسوَّى المستويات عند ‎-16 LUFS.
8. **ضبط الجودة** (`qc.ts`) — فحص ثابت على الجدول الزمني قبل الرندر (الأسماء،
   التواريخ، الشعارات، RTL، قصّ النص، المناطق الآمنة، المدة، الانتقالات) وفحص
   ديناميكي على الملف الناتج (الدقة، المدة، الإطارات السوداء، مستويات الصوت،
   حدّة الصورة). التقرير يُعرض للمستخدم مع كل برومو.

### النصوص العربية داخل الفيديو

محرّك الرندر يرسم المحارف كما تصله دون تشكيل أو ترتيب ثنائي الاتجاه، لذلك يتولّى
`text.ts` الأمرين: وصل الحروف إلى Presentation Forms ثم إعادة الترتيب RTL مع
إبقاء اللاتينية والأرقام بترتيبها. الخط **El Messiri** بوزنين
(`ElMessiri.ttf` للعناوين و`ElMessiri-Regular.ttf` للمتن)، ويسقط إلى `Cairo.ttf`
إن لم يتوفّرا.

### حدود المشاهد المولّدة

`genvideo` مقيّد في الشيفرة لا في التعليمات فقط: لقطات بيئية/معمارية/جوية للموقع
فقط، مع موجّه سلبي يمنع توليد الأشخاص والأنشطة التدريبية والشعارات. كل ناتج
يُحفظ موسومًا `generated: true` باعتباره **B-roll إبداعيًا لا توثيقًا لحدث وقع**.

### مكتبة المنصة الثابتة

الموسيقى والشعارات الرسمية ليست في الشيفرة ولا في المستودع. يرفعها **المدير**
مرة واحدة من **لوحة الإدارة ← مكتبة البرومو** (`/admin/library`)، فتظهر لكل
المنسقين في الاستوديو ويقتصر دورهم على الاختيار.

- **الموسيقى**: كل مقطع بعنوان وتصنيف و**ترخيص إلزامي** يُعرض للمنسق قبل
  الاختيار. ثلاثة مقاطع تكفي لتغطية الأنماط الستة، والنظام يرتّبها حسب ملاءمتها
  للنمط المختار.
- **الشعارات**: شعار الجامعة مدمج في المنصة ولا يحتاج رفعًا. تُضاف هنا شعارات
  الجهات الشريكة المتكرّرة، فيختارها المنسق بنقرة بدل رفعها في كل دورة.
- **التعطيل بدل الحذف**: تعطيل مقطع يمنع اختياره مستقبلًا دون المساس ببرومو
  أُنتج به سابقًا.
- يبقى للمنسق خيار رفع ملف موسيقي خاص ببرومو واحد، وهو استثناء لا الأصل.

الملفات تُخزَّن تحت `promo/library/music/` و`promo/library/logos/`، والصفوف في
جدول `promo_library` (قراءة لكل مستخدم مفعّل، كتابة للمدير وحده).

### التشغيل

الرندر عملية طويلة تعمل في عامل خلفي، لا داخل طلب HTTP:

```bash
npm run worker:promo            # تشغيل مستمر (يتطلّب ffmpeg و ffprobe)
npm run worker:promo -- --once  # دورة واحدة
npm run promo:check             # فحص ذاتي للمحرّك بلا ffmpeg وبلا مفاتيح
```

### الجداول

`promos` (إصدارات مرتبطة بـ `parent_promo_id`)، `promo_scenes`، `promo_assets`،
`promo_jobs` (طابور مع سحب آمن عبر `claim_promo_job`)، `promo_pronunciations`،
`media_analysis` — جميعها بـ RLS مربوط بملكية البرنامج، إضافةً إلى
`promo_library` لمكتبة المنصة، ودلو تخزين `promo`. المخطط في
`supabase/migrations/0003_promo_studio.sql` و`0004_promo_library.sql`.
